# Dataset

## Source

All data is synthetically generated by `src/data_pipeline/generate_telemetry.py`
(see `methodology.md` for why). There is no real-world or third-party
ransomware sample data in this repository.

## Schema

Each row represents one 500ms behavioral window for one process:

| Column | Type | Description |
|---|---|---|
| `pid` | int | Synthetic process id for this run |
| `run_id` | int | Unique id for one simulated process lifetime |
| `timestamp` | float | Seconds since the start of the simulated dataset |
| `window_index` | int | Position of this window within its run (0-indexed) |
| `write_rate` | float | File writes in this window |
| `rename_rate` | float | File renames in this window |
| `unique_dirs` | int | Distinct directories touched in this window |
| `files_modified` | int | Distinct files modified in this window |
| `entropy` | float | Mean Shannon entropy (0-8) of written file contents |
| `dir_dispersion` | float | Spread metric (0-1) of activity across the directory tree |
| `proc_cpu_pct` | float | CPU usage percent during the window |
| `handle_count` | int | Open file handles at the end of the window |
| `label` | int | 0 = benign behavior in this window, 1 = ransomware behavior |

`test_sample_concise.xlsx` (sheet `sample_windows`) is a generated
sample used by `train.py`, `evaluate.py`, `finetune.py`, and the
dataset-replay demo in `monitor.py`. Regenerate it at any time with:

```
python -m src.data_pipeline.generate_telemetry
```

which writes `data/telemetry.csv` using `generate_dataset()` -- pass
`n_stealthy_ransomware_runs` and `n_bursty_benign_runs` explicitly if
you want the harder confusable cases included (see the note in
`methodology.md`).

## Live-collected data

`src/live/real_collector.py` produces rows in the same 8-feature shape
in real time from actual file-system and process activity, but does
not (and cannot) set a ground-truth `label` -- that column is `None`
for every live row, since determining the label is the model's job.
